# 受託案件（クライアントワーク）ヒアリングチェックシート

受託案件では、自社タイトルと違って発注書の制約が絶対のルールになります。プロットを書き始める前に、以下がユーザーから聞き出せているか確認してください。揃っていない項目があれば、プロットに入る前に質問してください。

## ヒアリング項目

```
■Uへの提供価値：（このプロットで読者にどんな体験・感情を届けたいか。例：「大好きなカレのお誕生日をお祝いできる」）

■入れてほしい要素・ネタ：（発注側が指定する必須シチュエーション。例：「実家帰省」「〇年前の夏エピソード」）

■キャラ一覧と文字数対応表：
| キャラ名 | レアリティ | 文字数×話数 |
|---|---|---|
|  |  |  |

■文字数上限ルール：仕様字数の20%まで（例：2000字指定なら2400字が上限）

■目線指定：ヒロイン目線／彼目線／どちらでもOK

■既存キャラ設定の有無：新規のキャラ設定は基本的に行わず、渡された設定資料を踏襲する

■その他の制約：（季節感の必須/任意、他タイトルキャラとの共演可否、シリーズ通称と実際の配信名の違いなど）
```

## 記入例（「100恋+」VIPガチャ発注書より）

```
■文字数：
SR：3000字×2話（2話続き物にしてください）
R：2000字×2話
N：1000字×1話
※文字数超過は仕様字数の20%まで（2000字の場合は2400字が上限）

■Uへの提供価値：
好きな人と一緒に過ごすからこそ、その場所も時間も特別に感じられる
＝カレにとってヒロインがいかに特別な存在なのかがわかる。切な目エモ押しストーリー

■入れてほしい要素：
・SR/R 好きな人と一緒に実家帰省（実家がない場合は「実家代わりの場所」でもOK）
・SR/R カレの〇年前の夏（過去）エピソード
・N 子どもたちの夏休みストーリー（恋愛要素はなくてOK）
```

## 書くときのコツ

- レアリティ別に文字数・話数がバラバラでも、`outline-template.md` と `episode-detail-template.md` の型自体は流用できる。短いレアリティ（N等）ほど【序破急】を短編型（1話完結）で圧縮する。
- 「案件通称」と実際にストーリー上で描く内容が違う場合がある（例：通称「合同誕生会ガチャ」でも、実際は各キャラ単独の誕生日ストーリーを書く、他キャラを登場させる必要はない、等）。発注書の注記をよく確認し、額面通りに読み違えないこと。
- 受託案件は既存キャラのプロットがほとんどなので、キャラクター設定シートは新規作成せず、渡された設定資料の口調・過去傷などを踏襲して整合性を取ること。
